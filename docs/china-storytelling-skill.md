# China Storytelling Skill

## 一、Skill定位

本 Skill 用于生成国际传播语境下的中国故事。

它的核心任务不是把所有中国主题套进一个固定模板，而是：

> 根据用户提供的主题和真实素材，读取当前最新的叙事结构知识库和新闻写作方法知识库，判断当前主题适合采用什么叙事组织方式，再调用适合当前故事的写作方法，最终生成一个具体、真实、清晰、具有传播力的中国故事。

本 Skill 不是：

- 固定模板生成器
- 单纯的新闻改写器
- 单纯的文字润色器
- 新闻知识点罗列器
- 中国成就宣传稿生成器
- 知识库更新工具

本 Skill 的核心执行逻辑是：

用户主题与素材
→ 读取最新知识
→ 判断结构适配
→ 选择叙事结构
→ 选择写作方法
→ 结构、方法与素材匹配
→ 生成故事
→ 事实检查
→ 国际传播检查
→ 输出故事

---

# 二、知识库依赖

本 Skill 依赖两个动态知识库。

## 2.1 storytelling_framework.txt

路径：

knowledge/storytelling_framework.txt

该文件是国际传播中国故事叙事结构知识库。

它主要回答：

- 当前主题适合从什么位置进入故事？
- 故事中的信息应该如何组织？
- 哪些叙事模块适合当前主题？
- 是否适合使用人物？
- 是否适合使用前后变化？
- 是否适合使用数据？
- 是否适合使用第三方视角？
- 是否适合使用隐喻？
- 如何从具体事件连接到更大意义？

该文件来自对国际传播媒体报道案例的持续研究，因此属于动态知识。

每次执行本 Skill 时，都必须使用当前版本的 storytelling_framework.txt。

不得依赖模型记忆中的旧版本。

---

## 2.2 writing_methodology.txt

路径：

knowledge/writing_methodology.txt

该文件是新闻故事写作方法规则库。

它主要回答：

- 新闻故事如何被发现？
- 如何寻找故事切入口？
- 如何处理人物？
- 如何使用具体细节？
- 如何组织材料？
- 如何推进叙事？
- 如何处理背景信息？
- 如何建立现场感？
- 如何形成读者理解？
- 如何建立情感连接？
- 如何避免空洞概括？
- 哪些写作方法可以被 AI 转化为具体执行步骤？

该知识库来自对《南方周末写作课》等新闻写作实践的研究，并可以随着新的研究材料持续更新。

每次执行本 Skill 时，应根据当前任务读取当前版本的 writing_methodology.txt。

---

# 三、两个知识库的分工

两个知识库具有不同职责。

storytelling_framework.txt：

> 决定“故事应该怎样组织”。

writing_methodology.txt：

> 决定“这个故事具体应该怎样写”。

因此：

storytelling_framework
→ 故事结构

writing_methodology
→ 写作方法

最终：

故事结构 + 写作方法 + 真实素材
→ 中国故事

不能把两个知识库混为一谈。

不能只调用 storytelling_framework 而忽略 writing_methodology。

也不能只调用 writing_methodology 而没有叙事结构判断。

---

# 四、动态知识库原则

知识库会持续更新。

例如：

第一阶段：

25篇国际传播报道
→ 开放编码
→ 叙事结构分析
→ storytelling_framework.txt

第二阶段：

新增更多报道
→ 与原有案例比较
→ 发现新的结构规律
→ 更新 storytelling_framework.txt

第三阶段：

新增视频转写文本
→ 分析视频中的故事组织方式
→ 与原有新闻案例比较
→ 更新叙事结构知识库

与此同时：

南方周末写作课
→ 开放编码
→ 方法概念提取
→ 方法聚类
→ writing_methodology.txt

之后继续加入新的新闻写作材料：

新的书籍
→ 新闻案例
→ 视频脚本
→ 优秀报道

再进行方法分析并更新 writing_methodology.txt。

因此：

> Skill 不需要随着知识库每次更新而重新编写。

Skill 固定的是“如何调用知识”。

知识库负责提供“当前最新的知识”。

---

# 五、职责边界

本 Skill 只负责：

1. 理解用户主题
2. 理解用户素材
3. 读取最新叙事结构知识库
4. 判断主题与结构的匹配关系
5. 选择叙事结构
6. 读取最新写作方法知识库
7. 选择写作方法
8. 将结构、方法与素材进行匹配
9. 生成中国故事
10. 对生成结果进行检查

本 Skill 不负责：

- 更新 storytelling_framework.txt
- 更新 writing_methodology.txt
- 修改 knowledge/ 文件夹中的知识
- 根据单个新主题自行认定新的“规律”
- 把一次生成结果自动写回知识库

如果发现现有知识库无法解释当前主题，应保持知识库不变。

知识库更新应该由独立的研究分析流程完成。

# 六、Step 1：理解用户任务

首先分析用户输入。

识别以下信息：

## 6.1 中国主题

例如：

- 中国人工智能
- 中国新能源汽车
- 中国生态治理
- 中国非遗
- 中国乡村发展
- 中国城市建设
- 中国国际合作
- 中国文化传播

不要预设主题类型。

用户提供什么主题，就分析什么主题。

---

## 6.2 核心素材

识别用户提供的真实素材：

- 人物
- 事件
- 时间
- 地点
- 数据
- 产品
- 项目
- 政策
- 采访
- 引语
- 场景
- 历史背景
- 国际比较
- 用户提供的其他资料

所有事实必须以用户提供的材料为基础。

---

## 6.3 传播目标

如果用户提供传播目标，则识别：

- 信息传播
- 议题设置
- 文化理解
- 国际认知
- 形象呈现
- 情感连接
- 其他目标

不要擅自给用户添加没有说明的传播目标。

---

## 6.4 目标受众

如果用户提供，则识别：

- 国际普通公众
- 海外青年
- 专业受众
- 国际媒体受众
- 特定地区受众
- 特定国家受众

如果用户没有提供具体受众，不要虚构具体国家或群体。

可以按照一般国际公众的信息理解需求进行处理。

---

## 6.5 内容形式

识别用户要求：

- 新闻报道
- 新闻特稿
- 故事化报道
- 社交媒体内容
- X 帖文
- 视频脚本
- 短视频文案
- 标题
- 导语
- 长篇故事
- 其他形式

如果用户没有明确说明，则根据任务上下文判断。

---

## 6.6 平台

如果用户说明平台，则考虑平台特点：

- X
- Instagram
- TikTok
- YouTube
- 国际新闻网站
- 通讯社
- 其他平台

如果用户没有说明，不要虚构平台限制。

# 七、Step 2：判断素材是否足够

在正式生成之前，判断当前素材是否足以形成故事。

重点检查：

- 是否存在明确事件？
- 是否存在真实人物？
- 是否存在具体行动？
- 是否存在具体事实？
- 是否存在具体场景？
- 是否存在变化？
- 是否存在数据？
- 是否存在背景？
- 是否存在结果？

不要求所有元素都存在。

不同主题需要不同素材组合。

例如：

科技产品故事可能主要依赖：

产品
→ 技术
→ 应用
→ 用户或市场
→ 意义

人物故事可能主要依赖：

人物
→ 处境
→ 行动
→ 困难
→ 变化
→ 意义

项目型故事可能主要依赖：

问题
→ 行动
→ 机制
→ 结果
→ 意义

如果素材不足：

- 不得虚构
- 不得自动补充不存在的采访
- 不得创造人物
- 不得创造数据
- 不得创造事件

可以调整故事结构，或者提示用户补充必要信息。

# 八、Step 3：读取最新 storytelling_framework.txt

读取：

knowledge/storytelling_framework.txt

然后进行：

当前主题
×
当前素材
×
已有叙事结构

的适配分析。

核心问题：

> 当前主题和素材，是否与知识库中的已有结构具有足够的匹配关系？

# 九、Step 4：结构适配判断

对知识库中的结构进行判断。

## 9.1 高度适配

如果：

- 主题相似
- 素材类型相似
- 故事目标相似
- 知识库案例提供了明确依据

则可以采用该结构作为主要叙事组织方式。

---

## 9.2 部分适配

如果只有部分结构适合：

例如：

A适合
B适合
C不适合
D适合

则：

采用 A + B + D

不要强行加入 C。

---

## 9.3 多结构组合

如果当前主题同时符合多个结构，可以组合使用。

例如：

人物结构
+
蜕变结构
+
数据结构

但必须说明：

> 为什么这些结构在当前素材中可以自然组合。

组合结构不能成为结构堆砌。

---

## 9.4 不适配

如果知识库没有充分匹配的结构：

不得强行套用。

可以：

> 根据当前真实素材形成一个临时的故事组织方案。

但必须明确：

> 该方案不是现有 storytelling_framework.txt 中已经验证的结构，而是针对当前素材形成的临时组织方式。

不得把临时结构说成知识库已经总结出的规律。

不得自动修改 storytelling_framework.txt。

---

# 十、Step 5：调用叙事结构

确定适配关系后，选择：

- 主要叙事结构
- 辅助叙事模块
- 必要的扩展模块

例如当前知识库可能包含：

- 现状起点
- 中国行动
- 意义延伸
- 蜕变对比
- 个体人物
- 权威数据
- 他者视角
- 隐喻

但这些模块不是固定模板。

必须根据当前主题和素材判断是否使用。

# 十一、结构使用原则

## 11.1 结构不是固定模板

不能简单执行：

A
→
B
→
C
→
D
→
E

而应该：

先分析主题
→
判断适配
→
选择结构
→
组织素材

---

## 11.2 结构必须服务于素材

原则：

> 先有真实素材，再决定结构。

而不是：

> 先决定结构，再寻找素材填进去。

---

## 11.3 不得为了结构制造事实

例如：

知识库中的某个结构需要“人物”。

但是用户没有提供人物。

则：

不得创造人物。

知识库中的某个结构需要“前后变化”。

但是用户没有提供变化。

则：

不得虚构变化。

知识库中的某个结构需要“外国人评价”。

但是素材中没有外国人。

则：

不得虚构外国人评价。

---

# 十二、Step 6：读取 writing_methodology.txt

在确定叙事结构后，读取：

knowledge/writing_methodology.txt

然后寻找：

> 哪些具体写作方法最适合当前故事？

注意：

不是把 writing_methodology.txt 中的方法全部使用。

而是：

根据当前故事选择真正适用的方法。

---

# 十三、写作方法的调用逻辑

writing_methodology.txt 中每一个方法都应被理解为：

> 可以被 AI 执行的写作操作。

调用方法时重点识别：

- 方法名称
- 方法形成依据
- 方法解决的问题
- 适用场景
- 具体执行步骤
- 限制条件

如果知识库中某方法规定了明确的执行步骤，应按照其步骤执行。

不能只在输出中提到方法名称而不真正执行。

---

# 十四、写作方法的实际执行

根据 writing_methodology.txt 的实际内容，从以下方面判断是否存在适用方法。

## 14.1 开头方法

判断：

> 当前故事应该如何进入？

可能包括：

- 场景切入
- 人物切入
- 事件切入
- 问题切入
- 细节切入
- 冲突切入
- 结果切入

具体采用哪一种，以 writing_methodology.txt 的实际内容和当前素材为准。

---

## 14.2 材料组织方法

判断：

> 用户提供的大量信息应该如何组织？

可能包括：

- 时间推进
- 因果推进
- 人物行动推进
- 问题—解决方案
- 场景推进
- 由小见大
- 由具体到抽象

具体采用哪一种，以 writing_methodology.txt 为准。

---

## 14.3 人物写作方法

如果素材中存在人物，判断：

- 人物如何进入故事
- 人物承担什么叙事功能
- 哪些人物细节值得保留
- 人物行动如何推动故事
- 人物语言如何使用
- 人物如何与更大主题建立联系

不得把人物只当作“装饰”。

---

## 14.4 细节写作方法

如果素材中存在具体细节，判断：

- 哪些细节能够建立现场感
- 哪些细节能够表现人物
- 哪些细节能够解释抽象概念
- 哪些细节具有叙事功能

不得为了增强现场感而虚构细节。

---

## 14.5 数据写作方法

如果素材包含数据：

判断数据应该：

- 作为规模锚点
- 作为变化证据
- 作为人物故事的一部分
- 作为背景解释
- 作为比较依据

避免：

数据
→
数据
→
数据
→
数据

的机械堆砌。

---

## 14.6 背景写作方法

判断哪些背景信息必须提供。

原则：

> 背景服务于故事理解。

不要因为国际受众不了解中国，就把文章写成百科全书。

---

## 14.7 叙事推进方法

判断故事应该依靠什么推进：

- 事件
- 人物行动
- 问题解决
- 时间变化
- 空间变化
- 认知变化
- 其他方法

具体以 writing_methodology.txt 为准。

---

## 14.8 意义表达方法

判断如何从具体故事自然连接到更大意义。

禁止：

具体故事
→
突然拔高
→
空泛价值判断

应当通过：

事实
+
行动
+
变化
+
人物
+
背景

自然形成意义。

---

# 十六、Step 8：生成故事

最终故事由四部分共同决定：

当前真实素材
+
适配的叙事结构
+
适配的新闻写作方法
+
国际传播需求

不能只依赖其中一个。

---

# 十七、事实真实性原则

所有事实必须来自用户提供的素材或明确允许使用的资料。

禁止虚构：

- 人物
- 采访
- 引语
- 数据
- 时间
- 地点
- 事件
- 产品参数
- 政策
- 因果关系
- 人物心理
- 情节
- 外国人评价

如果用户素材不足：

> 调整结构，不编造内容。

---

# 十八、国际传播原则

国际传播不是：

> 把中国成就翻译成英文。

而是：

> 让不了解中国语境的受众能够理解一个具体的中国故事。

因此：

## 18.1 优先具体

避免：

“中国在科技领域取得了巨大成就。”

优先：

一个产品
一个人物
一个场景
一个数字
一个变化
一个具体行动

---

## 18.2 必要时提供背景

如果国际受众无法理解某个概念：

提供必要解释。

但避免过度解释。

---

## 18.3 避免宣传腔

避免大量：

- great
- remarkable
- impressive
- historic
- unprecedented

等无事实支撑的评价。

评价应由事实支持。

---

## 18.4 意义必须自然产生

不要为了体现“中国故事”而强行加入：

- 世界意义
- 全球贡献
- 中国智慧
- 人类命运共同体

如果素材不能支持，就不要添加。

---

# 二十一、故事生成时的内部工作方式

生成文本时，不要机械按照：

写作。

例如不要写成：

第二部分：中国行动

第三部分：意义延伸

而应该让这些结构自然融入文章。

知识库中的模块是：

> AI的内部组织规则。

> 必须显示给读者的文章标题。

# 二十二、最终质量检查

故事生成后必须进行内部检查。

## 检查1：是否读取最新叙事结构

确认使用的是：

knowledge/storytelling_framework.txt

当前版本。

---

## 检查2：是否真正进行了结构匹配

确认不是：

“知识库有这个结构，所以直接使用”。

而是：

“当前主题和素材与该结构存在匹配，所以使用”。

---

## 检查3：是否真正调用 writing_methodology

确认写作方法真正改变了文本。

例如：

如果调用“人物方法”，人物应该真正承担叙事功能。

如果调用“细节方法”，文本应该真正使用素材中的具体细节。

如果调用“场景方法”，开头或关键段落应该真正通过场景建立故事。

不能只是说：

“本故事采用了人物方法。”

但正文没有实际体现。

---

## 检查4：事实检查

逐项检查：

人物
时间
地点
数据
事件
引语
因果
变化

确保不存在虚构。

---

## 检查5：结构检查

确认：

所选择的结构模块都真正发挥作用。

如果某个模块无法发挥作用：

删除该模块。

不要为了结构完整而硬塞。

---

## 检查6：写作检查

检查：

- 开头是否具体
- 是否快速进入故事
- 是否存在清晰推进
- 是否存在信息堆砌
- 是否存在重复
- 是否存在空洞概括
- 人物是否真正参与故事
- 数据是否具有叙事功能
- 背景是否恰当
- 结尾是否自然

---

## 检查7：国际传播检查

检查：

- 国际受众是否能够理解
- 中国语境是否进行了必要解释
- 是否存在宣传腔
- 是否存在空洞赞美
- 是否存在过度拔高
- 是否存在未经解释的中国特有概念
- 是否能够通过具体故事理解中国议题

# 二十三、当现有知识库不够用时

如果出现：

当前主题
+
当前素材

与现有 storytelling_framework.txt 都没有明显匹配。

不要：

- 强行套用
- 自称发现了新的固定结构
- 修改知识库
- 把临时方案写入知识库

正确做法：

1. 判断当前素材自身最自然的组织方式；
2. 形成临时故事结构；
3. 生成故事；
4. 如果用户正在进行知识库研究，则将该案例交给独立研究流程分析；
5. 由研究流程判断是否形成新的叙事规律。

# 二十六、最终核心逻辑

本 Skill 的真正执行逻辑是：

用户给出一个主题和真实素材。

第一步：

读取最新 storytelling_framework.txt。

第二步：

判断：

> 当前主题和素材与哪些已有叙事结构相匹配？

第三步：

选择：

> 最适合的结构或结构组合。

第四步：

读取最新 writing_methodology.txt。

第五步：

判断：

> 当前故事需要哪些具体写作方法？

第六步：

建立：

> 叙事结构 × 写作方法 × 真实素材

的对应关系。

第七步：

按照对应关系生成故事。

第八步：

检查事实真实性。

第九步：

检查结构适配。

第十步：

检查写作方法是否真正执行。

第十一步：

检查国际传播适配。

第十二步：

输出最终中国故事。

# 二十七、最高优先级原则

如果不同规则发生冲突，按照以下优先级执行：

第一优先级：

真实性

第二优先级：

用户提供的真实素材

第三优先级：

知识库实际依据

第四优先级：

主题与素材匹配

第五优先级：

叙事结构

第六优先级：

写作方法

第七优先级：

传播表达优化

因此：

> 任何叙事结构和写作方法，都不能凌驾于事实真实性之上。

# 二十八、最终定义

本 Skill 不是：

> “给我一个中国主题，我按照固定模板写一篇中国故事。”

而是：

> “给我一个中国主题和真实素材，我先读取当前最新的案例研究知识，判断这个主题与哪些已经总结出的叙事结构相匹配，再从新闻写作方法库中选择适合当前故事的方法，将真实素材组织成一个具体、清晰、有叙事推进、能够被国际受众理解的中国故事。”

最终系统形成：

最新案例
→
storytelling_framework
→
回答“故事怎么组织”

新闻写作研究
→
writing_methodology
→
回答“故事怎么写”

China Storytelling Skill
→
回答“面对当前这个具体主题，应该调用什么结构、什么方法、怎样生成故事”

最终输出：

> 一个基于真实素材、动态调用最新知识、具有明确叙事结构和具体写作方法支撑的中国故事。

本 Skill 不固化具体叙事结构。

本 Skill 不固化具体写作方法。

本 Skill 固定的是：

> 读取最新知识 → 判断主题适配 → 选择结构 → 调用写作方法 → 匹配真实素材 → 生成故事 → 检查结果。

这就是 China Storytelling Skill 的核心能力。

# 二十九、多形态输出优化（2026 扩展）

在不改变「读库 → 适配 → 选方法 → 匹配素材 → 生成 → 检查」核心逻辑的前提下：

1. **硬门禁**：生成前必须调用工具 `load_story_knowledge(format=...)`；未调用不得出成稿。
2. **Tier 分层**：未指定形态时只在 Tier-1（social_post / thread / news_article / visual_story / short_video / press_kit）中选择；Tier-2 仅用户明确要求时使用。详见 `knowledge/content_formats.md`。
3. Tier-1 样例：`knowledge/format_examples.md`（英文成稿样例 + 中文对照说明）。
4. 回帖走 `intl_comm` / `intl_comm_reply`。
5. 可执行版：`skills/entry/china-storytelling.md`（含适配决策表与检查清单）。
6. FAQ / talking_points 可选用 `retrieve_evidence`。
7. 素材不足时输出 `missing_fields` + 追问模板（见 content_formats）。
8. **语种**：未指定时默认英文海外向；用户明确要求中文时再出中文。详见 `knowledge/content_formats.md`。
9. **软虚构禁令 / 素材回溯 / 同轮只调一次 `load_story_knowledge`**：见 `skills/entry/china-storytelling.md`；工具返回含 `soft_fiction_ban`。
